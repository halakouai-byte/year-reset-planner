## 1. What the project is

2027 Year Reset Planner Pack: a printable PDF planner, "2027 Year Reset
Planner" — 14 pages, A4: 2026 review (wins, lessons, numbers), 2027 vision
+ goals by life area, top-3 goal breakdowns, 90-day plan (Q1 focus +
weekly rhythm), monthly check-in, 365-day habit tracker (3 habits), BONUS
Year-End Money Close-Out (accounts, debts, subscriptions audit, net
worth), commitment page. Sold for **$3.00 USDT on TON** (TON only at
launch). Payment is crypto-only (USDT on TON mainnet) via a Telegram bot +
a free landing page; the product file is delivered automatically by the
bot after the Worker verifies the payment on-chain. No AI runs at
runtime — the product is a static file. Seller is in Iran: no KYC, no
PayPal/Stripe, no central-exchange payouts.

Seasonal product: list by ~Nov 28, 2026. The buying window peaks
Dec 26–Jan 15 and is effectively dead after Jan 31, 2027. After the
window, the product stays listed (evergreen late buyers) but no new
marketing spend goes to it.

## 4. Deployment

- **Cloudflare Pages** — project `year-reset-planner`, production URL
  `https://year-reset-planner.pages.dev`. **Connected to this repo natively
  (Cloudflare ↔ GitHub): every push to `main` auto-deploys `site/`** — no
  build command, deploy root `site/`, preview builds off, no GitHub secret
  needed for Pages. Do NOT deploy Pages with `wrangler pages deploy`.
  Verify a deploy by pushing to `main` and checking the live URL (HTTP 200).
- **Cloudflare Worker** — name `year-reset-bot`, URL
  `https://year-reset-bot.halakouai-byte.workers.dev` (workers.dev subdomain
  `halakouai-byte`). Cron trigger `*/2 * * * *` (payment sweep, set from
  `wrangler.toml` `[triggers]` by `wrangler deploy`). KV namespace binding
  `ORDERS_KV`. Deploy only with `wrangler deploy` from `worker/` — never
  hand-roll the script-upload API.
- **Worker secrets — NAMES ONLY, never values, never in the repo.** Set with
  `wrangler secret put <NAME>`: `BOT_TOKEN`, `SELLER_TON_ADDRESS`,
  `PRODUCT_FILE_ID`, `WEBHOOK_SECRET`, `SELLER_TELEGRAM_ID` (gates the
  seller-only bot commands `/refund`, `/deliver`, `/orders`; disabled if
  unset), optional `TONAPI_KEY`. Non-secret vars live in `wrangler.toml`
  `[vars]`: `BOT_USERNAME`, `SUPPORT_USERNAME`,
  `PRODUCT_PRICE_USDT="3.00"`, `ORDER_TTL_MINUTES="60"`.
- The Worker returns `{"ok":true,"service":"year-reset-bot",
  "price_usdt":"3.00"}` on `GET /health`. If it 500s on every route, a
  required secret is missing (the config check throws).

## 5. How a sale works end to end

1. Buyer opens the landing page and taps Buy. The page calls
   `POST /api/order` on the Worker (or falls back to the bot link if the
   Worker URL is unset).
2. The Worker creates an order with a unique memo `YR-XXXXXX` (60-minute
   expiry) and returns a Keeper/`ton://` pay link for **$3.00 USDT on TON
   mainnet** (price in USDT, never TON; TON floats). The memo is the order
   id — the buyer must not edit or delete it.
3. The buyer pays from their wallet, then taps "I paid" in the bot (or
   waits — the 2-minute cron sweep also checks).
4. The Worker verifies the payment on-chain via TonAPI jetton history
   (primary; TON Center v2 fallback for native TON): the transaction must
   match the order's memo **and** amount. Wrong amount / missing memo /
   wrong network (USDT on TRON/ERC-20 instead of TON) → **never
   auto-deliver**; the order goes to manual review and the seller resolves
   it with `/deliver`.
5. On a verified match the Worker tells the bot to deliver: the bot sends
   the product PDF via `sendDocument` using the cached `PRODUCT_FILE_ID`.
   A tx-hash claim recorded before delivery prevents double-delivery; a
   `paid`-but-undelivered order self-heals on retry / cron sweep.
6. Refunds are manual: the seller sends USDT back from their wallet; the
   bot only records the refund. There are no chargebacks in crypto.
- **Telegram Stars rule (§6.2 of the Bot Platform Developer Terms):**
  digital goods in bots/Mini Apps must be sold exclusively in Telegram
  Stars. Mitigation built into this project: payment happens on the
  **external landing page only**; the bot is delivery/support only. This
  is a partial mitigation, not total — state it honestly, do not claim the
  risk is gone.
